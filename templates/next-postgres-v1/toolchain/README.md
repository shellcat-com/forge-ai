# Candidate image input contract v1

Agreed with Task 02 on 2026-09-10 UTC. No image is released. Task 03 owns template bytes, dependency acquisition/review, protected policy and export reference files. Task 02 owns immutable Linux assembly, launch and real containment evidence. The scaffold and reference migrations are platform-authored; they are not generated output.

1. On a trusted networked acquisition machine, use Python 3 and curl to run `python3 templates/next-postgres-v1/toolchain/acquire.py /absolute/new/bundle`. It fetches every locked package, including other platforms' optional dependencies; verifies SHA512 SRI, registry/lock/package identity and license metadata; inventories actual license file hashes and lifecycle commands without executing/extracting archives. Store the immutable bundle privately outside Git. Review metadata, hooks, notices and advisories. Missing provenance is recorded rather than manufactured.
2. Pin the SHA256 of `dependencies.json` and `registry-keys.json` in the reviewed image-input manifest. The bundle digest identifies the canonical content set; npm cache indexes/timestamps do not define reproducible content. Verify registry keys against the pinned digest before import. Run `node toolchain/materialize.mjs BUNDLE DEPENDENCIES_SHA256 KEYS_SHA256 NPM_ROOT NEW_CACHE linux-x64` using checksum-verified Node 24.20.0 and bundled npm 11.19.0. This imports verified bytes offline and verifies registry signatures; it does not verify Sigstore provenance. `npm audit signatures --json` is a separate networked provenance verification step, with dated output retained. No hook is approved for execution.
3. In the isolated Linux image with no NIC, copy the authenticated immutable source from `/workspace` to disposable `/scratch/build`; provide the content cache read-only as an image input, copying cache state to scratch if npm needs writes. Run the exact pinned npm CLI with `ci --offline --ignore-scripts --no-audit --no-fund --cache SCRATCH_CACHE`. Clear ambient npm config/NODE_OPTIONS/secrets. npm verifies lock integrity again. Never resolve missing packages online. The Linux GNU x64 SWC/esbuild/rollup/sharp optional packages must be installed and usable without hooks; this must be tested on the actual image.
4. Resolve existing `policy.ts` logical commands to immutable trusted CLI paths. Build/check configuration, `platform/`, dependency manifests, database bootstrap and reference files are protected catalog entries. Generated source cannot change their hashes or add root config/test files. Run lint, strict TS, protected Vitest and Next webpack production build independently. Never trust package-script edits or app-supplied check results. External CRUD/browser/restart tests belong to the independently isolated harness.
5. Task 02's `imageDigest` is `sha256:` plus the canonical hash of its versioned image bundle manifest binding guestKernel, rootfs, Firecracker, jailer, seccomp, dependencyCache, guestAgent, imageInputsDigest and templateInputsDigest. `templateInputsDigest = canonicalHash({schemaVersion:1,files:sorted([{path,mediaType,sha256,bytes}])})` using existing E2 canonical JSON (UTF-8, sorted object keys, no trailing newline). It has no image field. Compute imageDigest next, then the unchanged E2 `templateCatalogDigest`, which includes imageDigest. The signed broker descriptor binds both final image/catalog digests. Never put the final E2 templateDigest into the image preimage. No circular image digest in rootfs: per-launch immutable metadata carries descriptor/RPC material. `/opt/forge` holds immutable catalog/tools; `/workspace` is read-only; `/scratch/build` is untrusted. PostgreSQL is guest-loopback only; vsock RPC supplies guest-private credentials. No provider/control/deployment credentials enter the guest.
6. PostgreSQL bootstrap is `app-database.sql`; generated SQL still passes the engine's additive parser and reviewed ordered hash list before guest transaction. `reference/migrations/` contains exact retained task-board/priority fixtures. Fresh and prior-seeded scenarios must run against separate disposable databases. `platform/reference-migrate.mjs` is an idempotent export reference drill, not the general guest migration service. Absent trusted prior-state/external harness coverage fails acceptance.

The release manifest must record actual kernel/rootfs/toolchain/cache/source/command hashes, Linux distribution/libc/compiler/build flags and package/license inventory. Acquisition from an HTTPS checksum endpoint is integrity evidence, not a verified upstream signing chain. Task 02 must provide deterministic image assembly inputs and a second-build comparison before claiming image reproducibility. Currently those image fields are unavailable, not placeholders.

Portfolio reference: `reference/portfolio.json` is an acceptance brief. A proposed **separate** `portfolio-static-v1` profile would protect Next `output: 'export'`, omit server/Route Handler/DB features, collect `out/` into `build/static/`, and bind every public asset plus output digest to reviewed source. It is not implemented/approved in this task-board template. Task 08 must keep publishing disabled until that distinct profile and actual runner/provider evidence exist. A public portfolio never closes the engine's PostgreSQL acceptance.

Package Linux cache content with `python3 toolchain/package-cache.py CACHE NEW_ARCHIVE.tar`. The packager rechecks each SHA512-addressed content file and emits sorted PAX entries with fixed metadata; compare two outputs. `dependencyCacheArchiveSha256` is the actual archive hash, distinct from the logical dependency manifest hash. The recorded cache was prepared on macOS and has not executed in Linux. Recompute candidate image inputs from reviewed repository files with `npx --no-install tsx templates/next-postgres-v1/toolchain/write-inputs.mts`; the canonical hash of that JSON object is imageInputsDigest (file whitespace is not hashed).
