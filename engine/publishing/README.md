# Portfolio publication boundary

This module prepares a narrowly scoped static artifact. It is not a public deployment endpoint, generated-code executor, release authority or working hosted builder. The canonical Next.js frontend remains the intended application. `/hosting` and the opt-in static frontend packager render the same temporary unavailable component.

`preparePortfolioPublication(publicationId, authority, signal)` requires a **trusted server composition**. Task 01 must implement `PublicationAuthority` using current owner authorization, immutable source/storage records, authenticated broker evidence and separately recorded publication/content approvals. Do not bind `loadApproved` to request JSON or infer authenticity from `origin: runner`. No live implementation is registered here.

The authority must verify the real provider call/accounting evidence, approved template release/profile, signed runner descriptor and result, current snapshot/policy/revocation state, owner-approved content and exact Vercel target before returning a record. The pure validator preserves those bindings and rechecks permission after artifact I/O. Publication is separate from source promotion. Test factories intentionally simulate this authority; their provider/runner strings cannot establish live provenance.

The proposed `next-postgres-portfolio-static-v1` profile requires a Task 03 protected Next.js export configuration and Task 02 collector output entirely under `build/static/`. It is **not approved or implemented by the current task-board template**. Canonical collector order and `{path, bytes, sha256}` entries must exactly hash to the authenticated verification's `buildOutputDigest`; public bytes retain their exact hashes after stripping the fixed prefix. No source/Functions/server bundle/config/credentials/source maps are sent to Vercel. Strict CSP blocks browser connections, forms, frames and workers. Inline scripts/styles are also blocked: a Next.js export needing hydration must supply an independently reviewed CSP/profile adaptation before publishing; never silently allow unsafe inline code.

The static profile is limited to 200 files / 10 MiB. Binary font/image decoding and arbitrary JavaScript semantics are not proven safe by a filename allowlist or secret heuristic. Pair real source/content review, secret scans and isolated browser evidence with the fixed CSP. The task board still needs real PostgreSQL CRUD, app-process restart and additive priority migration; static portfolio publication cannot satisfy that acceptance.

`writePrebuiltDirectory` writes a new private staging directory under a caller-owned private parent. It never executes generated code. A malicious process with the same filesystem identity can still interfere; this is an operator staging tool, not a multi-tenant storage service. `validateVercelTarget` consumes authenticated API observations and requires exact project/account/name, no Git link, no environment variables, and no server build commands/framework. Empty project metadata is not a spending grant or authorization.

Deployment procedure: create only the exact dedicated authorized project, inspect it again, write `.vercel/project.json` with its verified project/team IDs, verify every staged byte against the receipt, and use `vercel deploy --prebuilt --prod --scope TEAM --yes` from the clean stage. Never use `vercel build`, `vercel pull`, Git autodeploy or repository-root deployment for generated code. Tokens stay in the operator CLI environment/credential store, never build output. Record deployment intent before the CLI call; if the response is ambiguous, inspect deployments instead of retrying blindly. The CLI command is an explicit operator action, not an automatic call from a generated app.
