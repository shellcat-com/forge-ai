# KVM runtime implementation and deployment contract

The runtime is **implemented but uninstalled and unvalidated on Linux**. `UnavailableFirecrackerDriver` remains the default. Imports, repository tests, Vercel hosting and image packaging do not enable it. No root runtime configuration, accepted image, isolated external harness or live control authorization adapter is shipped.

## Components and authority

`FirecrackerDriver` implements the existing `HostDriver` signature. Wire it only behind `SandboxBroker` with authenticated mTLS peers, pinned signing keys and `BrokerOptions.authority` reading current locked E1 state. Task 01 owns that adapter and the real stage-result bridge. No engine/control schema or origin literal is widened by this task. `FirecrackerLinuxExecutor` invokes one installed root-owned helper with fixed JSON operations; no candidate shell, executable path, inherited environment or host process fallback exists.

`HostLeaseSupervisor` retains reservation/tombstone behavior. The Python helper adds its own fsynced operation intent, singleton flock, never-reused identities, monotonically fenced lease and permanent tombstone. Launch holds the lock through the systemd transaction. Per-attempt lease watcher starts before the VM, polls every 250ms and stops it without broker/control connectivity. The transient VM unit has an independent maximum active runtime; stop masks the unit before cancellation so delayed `systemd-run` cannot resurrect it. Child utility processes get a parent-death SIGKILL. Cleanup waits for absent pending systemd jobs, inactive launcher/VMM and empty cgroup; storage/key removal precedes positive absence observation. Failed or ambiguous cleanup retains quota. The existing supervisor watchdog must also be running. Host reboot recovery must fence prior ownership before reopening its inventory; never delete an owner lock to bypass this rule.

Every host runtime/jail ancestor is checked with lstat for root ownership, directory type and absence of group/world write. Attempt directories are created exclusively; a durable jailCreated record is required before cleanup may delete an existing directory. Binding, wipe and observation recheck protected ancestors; deletion is relative to a no-follow directory descriptor. Existing/symlink/substituted paths fail closed.

Launch uses the matched static Firecracker/jailer pair, explicit seccomp filter, immutable kernel/rootfs copies, fixed-size ext4 scratch and a read-only per-launch metadata disk. It never mounts a guest filesystem on the host. No virtio network interface is configured. systemd isolates the VMM network namespace; guest nftables allows loopback only. The app gets app-local PostgreSQL over `127.0.0.1:5432`, not any host/control database. VMM memory has a separate 256MiB management allowance; guest memory remains the descriptor limit. Guest app/check processes share one root-controlled cgroup slice. Scratch capacity covers source, build, logs and PostgreSQL. Reserve image copies, metadata disks, VMM and watcher overhead separately in physical host sizing.

## Image hash preimages

`runner/image/contract.ts` strictly parses:

```text
{schemaVersion:1, architecture:"x86_64", isolation:"firecracker-jailer-vsock-v1",
 templateInputsDigest, imageInputsDigest, guestAgentDigest,
 assets:{firecracker,jailer,guestKernel,guestRootfs,dependencyCache,seccompFilter,supervisor}}
asset = {path:"/opt/forge/...", sha256:<actual file SHA256>}
imageDigest = "sha256:" + canonicalHash(parsed bundle)
```

Canonicalization is engine canonical JSON v1: sorted UTF-16 keys, UTF-8, safe integers, unchanged arrays, no trailing newline. Paths are part of this versioned preimage and cannot move without changing imageDigest. Each asset and its parents must be root-owned, real/no-symlink paths; files have no write bits, parents have no group/world write bits. Expected install modes: executable assets 0555/0500, data 0444, protected metadata 0400/0600, private runtime directories 0700. The helper verifies itself against `assets.supervisor` and hashes every pinned asset before launch. This is measured integrity, not attestation of containment.

Task 03 supplies `templateInputsDigest`: canonicalHash of `{schemaVersion:1,files:[{path,mediaType,sha256,bytes}]}` sorted by path over reviewed exported bytes. This independent input excludes final image/catalog hashes and acquisition metadata. `imageInputsDigest` is canonicalHash of parsed Task 03 image-input JSON (engine canonical JSON v1, no newline). The packaging receipt separately records `imageInputsFileSha256` over exact raw file bytes, including formatting/newline. `guestAgentDigest` hashes the agent.py bytes baked into rootfs; packaging receipt additionally hashes every installed platform file. `dependencyCache.sha256` hashes an actual cache image/archive; the logical dependency-set manifest digest is **not** a cache archive digest. The rootfs must contain the verified extracted cache, exact Node/PostgreSQL and dependencies, with no acquisition credentials.

Compute imageDigest first, then E2's existing final template catalog digest (which includes imageDigest). Pin accepted final template digests separately in root configuration; the signed descriptor binds image, final template, source and command policy. There is no recursive imageDigest/templateDigest hash and no placeholder release hash.

`runner/image/assemble.py` packages a **trusted, operator-prepared** Linux root tree into ext4, adds pinned platform files and writes a packaging receipt. It performs no network downloads or host installation. The packager consumes Task 03's actual `image-inputs.json`, a separate `--assets` JSON mapping of the six pre-rootfs host assets, and `--toolchain-archives`; it verifies archive/cache byte hashes and every prepared cache file against the archive without extracting it. Prepared binary/tree contents and distribution configuration still require operator review and Linux execution against those pins. The receipt is `packaged-unvalidated`; it is not a release or offline execution pass. No image was packaged in this task.

## Guest RPC and commands

RPC is host-initiated Firecracker vsock on port 4100 via the trusted operation/attempt socket. Each request/response is length-framed (1MiB maximum), HMAC-SHA256 authenticated with a random launch-only key, and binds operation, attempt, image, source, epoch, request nonce and request digest. The guest rejects replay/foreign binding and an expired, timezone-less or more-than-60-seconds-future request deadline before modifying epoch/nonce state or dispatching a handler. Guest wall-clock availability/drift must be qualified on the real image; an invalid clock fails closed. Only host CID may connect. Generated app units cannot create AF_VSOCK sockets; RPC/migrator keys remain root-private. The guest is still untrusted: a transport MAC does not turn a guest result into independent correctness evidence.

Approved manifest plus per-file bytes are checked on both sides. Source transfers in 48KiB chunks, total <=10MiB/200 files, then is sealed at read-only `/workspace`. Commands work in disposable `/scratch/build`. Direct fixed commands implement offline npm materialization (`ci --offline --ignore-scripts --no-audit --no-fund --include=dev`), eslint, tsc, vitest and Next production build. No npm package scripts or lifecycle hooks are approved. All generated command output is discarded; zero bytes is within the log cap. Evidence records contain structured status/digests only. A failed process is not inferred to be OOM; systemd Result is observed. Native/Linux testing must validate exact cgroup counters and exhaustion behavior before admission.

Guest PostgreSQL uses independently random 32-byte hex app and migrator credentials, SCRAM, nonsuperuser roles, application connection limit 5 and migrator limit 1. Privileged platform bootstrap reads pinned app-database.sql; passwords go to psql stdin, never SQL logs. Only `forge_app` DATABASE_URL enters generated-code process environment. Canonical approved migration statements come from the host's existing strict SQL parser after exact review/source checks and run as `forge_migrator` in a bounded transaction. Fresh database, prior-seeded database and app-process restart are distinct acceptance cases.

`IsolatedExternalChecks.run` is deliberately a required **separate isolated test guest** dependency. It gets exact source/check identity and a bounded app request/restart capability, not a host path, arbitrary URL or platform credential. No local Playwright/Node process substitutes for that environment. Its real image/allocation/runner implementation and prior-seeded fixture remain unconfigured; absence throws. This task implements isolated app access and the runtime interface, not a fabricated passing external harness. Task 01 must reserve/authenticate that additional environment, and Tasks 03/09 must pin its trusted browser/check bytes before live integration.

Collection quiesces the guest app slice and frames individual regular files. The host collector rejects traversal, links, devices, archives, duplicate paths and length mismatches; total <=1GiB/10,000 files and a 5-second collection deadline. `.next/cache`, diagnostic and generated type directories are excluded. This conservative deadline may reject a large valid build; such rejection retains quarantine, not success. No guest archive is extracted or mounted on the host. Sink/evidence callbacks must be trusted bounded private artifact stores (Task 06).

## Preview contract with Task 07

```ts
health(descriptor, signal): Promise<{processReady: boolean; databaseReady: boolean}>
requestApp(descriptor, {method,path,headers,body:Uint8Array}, signal)
  : Promise<{status,headers,body:Uint8Array}>
```

Task 07 resolves its immutable generation/environment/operation/epoch through authenticated registry and current HostInventory; it never accepts a browser-supplied descriptor. The driver resolves helper binding before **and after** RPC. Health requires app-role `SELECT 1` and fixed `/api/health` HTTP 200. HTTP always targets guest loopback port 3000 with no redirects, 10-second deadline, request <=256KiB and response <=512KiB. Cookies, authorization, Host and forwarding headers are rejected; response cookies/redirects are not forwarded. No public socket/URL is returned. WebSockets/streaming and larger assets are unsupported by v1.

Ordinary heartbeat retains the epoch and extends expiry. A takeover/new epoch must get a fresh preview generation via Task 07; old-epoch requests fail. Expiry equality with the current helper record is enforced. Cancellation tombstones deny new bindings immediately and post-response checks discard in-flight output. Global source/check lifecycle and verified preview preparation remain Task 01 integration; an allocated VM alone is not app readiness.
