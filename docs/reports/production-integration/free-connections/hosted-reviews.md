# Hosted owner plan review and resume

2026-09-11. This adds the plan approval boundary; it does not enable the full builder or approve execution/publication.

`HostedReviews` reads the owner's plan from encrypted immutable PostgreSQL objects outside control transactions, then repeats current account and metadata authorization. Explicit plan approval binds the exact review hash/state, original admitted login, current key/model/free policy, project revision and cancellation state. Approval, state transition, next canonical job step and new scheduler outbox intent commit atomically. Replayed retry identities return the original response. A different login can read owned saved work but cannot silently replace the original job's session authority.

The Node route `GET /api/control/jobs/:id/plan` reads the plan. `POST` at the same path explicitly approves it with an `Idempotency-Key` header and `{schemaVersion:1,stateVersion,subjectDigest}` JSON. The existing Better Auth adapter validates current user access and same-origin mutations; engine session/CSRF handles remain server-side. Responses, including errors, use `Cache-Control: no-store`. Driver details and server credentials are not returned. The route does not call a model, start a runtime, publish or automatically approve a plan.

The route is disabled unless `FORGE_HOSTED_SOURCE_REVIEW=true`. No deployment settings were changed. Server composition additionally requires the existing hosted auth/control configuration, separate `FORGE_OBJECT_READER_DATABASE_URL` on the exact `FORGE_CONTROL_DATABASE_HOST`, `FORGE_OBJECT_KEY_ID`, and bounded `FORGE_OBJECT_KEY_REFERENCES_JSON` mapping key IDs to protected `FORGE_OBJECT_KEY_*` environment variables. These are references and private server configuration, never browser fields. The actual restricted reader login is checked before use; rejected readers are closed and not cached as valid. Keep historical decryption keys for retained objects. Enabling review does not enable admission or workers; approvals require current database admission/worker authority and zero-cost policy.

Verification before combined integration: 37 native PostgreSQL gate/product/review tests passed, and 7 thin-route composition tests passed on Node24.20.0. The native suite uses real restricted SQL/object roles and encryption but synthetic accounts, model policies, catalog metadata and provider usage. Route tests explicitly mock account/storage/core service boundaries; they do not claim live HTTP or account acceptance. Native checks include exact plan read, retry deduplication, stale hashes/revisions, key/logout/cancel/policy changes, owner/CSRF denial, logout during storage I/O, a new-login fence, and rollback of approval/state/step when outbox insertion fails.

The first native review run failed ten tests because its synthetic review expiry did not match the canonical reducer. The fixture now uses the same database clock/deadline as the unchanged reducer; all 37 tests passed on rerun. [Failure and passing evidence](evidence/hosted-reviews/sha256.json) is retained separately. Lint and both typechecks passed; combined worker/build/CI results are recorded in PR18 after integration.
