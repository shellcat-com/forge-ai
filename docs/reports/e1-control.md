| Gate | Required input / blocked integration |

| D4 | Approved price versions, token bounds and model/infrastructure spend envelopes. E1 tests synthetic caps and retained uncertainty; no paid call or real compute/storage admission is enabled. |

Operator flag tables and internal reconciliation are implemented; production administration transport, real invite management, telemetry/alerting, audited release operations and capacity certification remain gated. The fixture cleanup adapter confirms simulated inventory only; it is not host termination/quarantine evidence. A live integration must add authenticated resource-specific receipts and preserve cleanup-generation/lease fencing. E0 append-only migration, approval, event and accounting protections were not relaxed for cleanup or retention.

A01–A22 remain incomplete as end-to-end release acceptance. E1 adds concrete control-plane evidence for A03/A05–A10/A15–A18/A21, but does not replace real source generation, executable checks, clean export, isolated persistence, private preview, browser accessibility or load/quality acceptance with fixtures.

## Exact E2 handoff

Continue inside this control service and the existing E0 contracts. Review and reuse concurrently authored `engine/generation/`, provider/artifact/validation modules and `templates/` before adding replacements; their separate reports do not establish live E1 integration. Preserve 0001 and 0002; append migration 0003 for new persistence contracts.

1. **Catalog admission seam.** Replace hard-coded imports from `control/catalog.ts` with an injected server-owned catalog. Keep the current synthetic catalog as the default. A separately named E2 fixture catalog may use a fixed zero-cost policy digest and explicit non-release template candidate. Admission must resolve immutable template/image/policy/prompt/model identity from server configuration; clients cannot choose endpoint, credentials, arbitrary images or prices. D7 candidate evidence must not be silently promoted to an approved release.
2. **Use the existing worker boundary.** Integrate a source stage adapter through `StageAdapter.run(StageInput, AbortSignal)` for PLANNING, GENERATING and REPAIRING. Preserve tenant/project/job/step/epoch/operation/input binding and the worker’s locked commit path. Do not introduce a second job service or give an adapter session, approval, promotion or database mutation authority. Fixture-only catalog/artifact integration may proceed with `origin: fixture`, zero cost and execution/preview disabled. A real adapter/provenance mode needs separately reviewed gates and additive SQL; do not remove fixture-only guards to make tests pass.
3. **Durable per-call accounting before live/multi-call dispatch.** E1 currently records one bounded provider attempt per stage (`provider_attempts` has a job/step uniqueness constraint). Add a versioned per-call intent/reservation/result interface and additive schema for multiple batches/retries before an adapter can issue real internal calls. Persist exact input digest, operation identity, token/price upper bound and liability before every request; cap total calls/repairs/retries, retain ambiguous outcomes and fence/deduplicate completion. No unmetered calls hidden inside an adapter; no replay of uncertain paid calls. D3/D4 closure is required for actual provider requests.
4. **Context, parser and source pipeline.** Assemble the approved brief/plan/base manifest, pinned template, allowed owned files and bounded sanitized diagnostics. Validate provider streams/completion/refusal/truncation/usage through E0 contracts; preserve cancellation and fixed destinations. Apply whole-proposal limits, prior hashes, ownership, protected paths and migration policies before writing candidates. Repair must produce a new immutable candidate/diff and fresh execution review. The required output remains Next.js + strict TypeScript + PostgreSQL.
5. **Immutable artifact bridge.** Introduce a narrowly scoped read port for an authorized base snapshot and staged `StoredSource`/diff references with immutable object versions, byte counts and raw SHA-256 values. E1 fixture source blobs currently store JSON wrappers; their wrapper hashes are not raw-file hashes. Validate both raw blobs and manifests correctly. Only a current leased worker transaction may adopt staged refs into available artifacts/candidate history and publish events. Keep orphan staged writes inaccessible and reconcile them safely after crashes. Add tenant-safe plan/changes/file/export reads when their actual artifact contracts are present; no arbitrary URL/path access. D5 blocks real object-store/KMS deployment and data retention choices.
6. **Evidence and E3 boundary.** Test the integrated E1 → E2 fixture path, malformed provider streams/batches, wrong-context/object hashes, stale approvals, repaired candidates, cancellation during staging, stale-worker adoption and crash/replay with native PostgreSQL. Run `npm run verify`, `npm run test:db:e1`, `npm run test:db:control` and applicable source-pipeline checks. Publish an E2 report separating fixture tests, approved live-provider evidence and blocked decisions. Leave PROVISIONING/VERIFYING/PREPARING_PREVIEW on explicit E1 fakes until E3 supplies authenticated broker requests, exact descriptor/evidence validation, host isolation, app-local PostgreSQL and confirmed cleanup; no generated execution is authorized by this handoff.

E2’s independent exit is a validated, immutable, reviewable source pipeline connected to this durable control service with honest fixture provenance and no regression of E1 fencing/accounting. Live E2 acceptance additionally requires approved D3/D4/D5/D7 inputs and measured provider results. E3/E4/E5 own actual isolated execution, private preview and vertical-slice/release acceptance.
