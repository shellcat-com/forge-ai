# RFC 0001 amendment proposal — private preview with no domain purchase

2026-09-10. Task 07 proposal for Task 01 integration into RFC 0001 §12/D6. **Not a deployed preview or D6 closure.** Next.js + strict TypeScript + PostgreSQL, open-source BYOK, Vercel website hosting and the separately published Task 08 portfolio remain the required direction. No infrastructure or API spend is authorized.

## Browser boundary and hostname decision

Replace the requirement to buy/control a separate registrable domain with a requirement for a separately verified **schemeful site and origin** for each immutable preview generation. Ownership of a purchased domain is unnecessary if a provider-issued hostname supplies that boundary. Do not substitute path prefixes, ports, branch aliases or arbitrary different hostnames for browser evidence.

Vercel generates deployment addresses and distinguishes immutable deployment URLs from branch/production aliases that move to a newer deployment. Generated URLs are publicly accessible by default; protection is a separate setting. Use only the actual returned unique deployment hostname for a generation, record it once, and retain its tombstone after cleanup. Do not invent an address from a project name or reuse an alias. [Vercel generated URL documentation](https://vercel.com/docs/deployments/generated-urls).

The Public Suffix List includes `vercel.app`. In Chrome 153.0.8010.36, this task's HTTPS loopback test observes `Sec-Fetch-Site: cross-site` when navigating between two sibling `vercel.app` hosts; attempting `Domain=vercel.app` sets no cookie. A positive control navigating from `forge-task07.vercel.app` to `child.forge-task07.vercel.app` reports `same-site` despite distinct origins. Host-only Forge cookies remain withheld. The browser also prevents script overwrite of the gateway's Secure/HttpOnly `__Host-` cookie. These are real browser observations with synthetic local DNS/TLS routing, **not verification of issued Vercel hosts or public TLS**. [PSL source](https://publicsuffix.org/list/public_suffix_list.dat), [local browser evidence](evidence-task-07/browser.json).

## Candidate arrangement

A separate Vercel project containing only the trusted gateway could receive an immutable generated HTTPS hostname for each environment generation. Require Vercel Authentication with **All Deployments** protection, including every alias, plus Forge's independent current viewer authorization. Standard Protection excludes production domains and is insufficient as the only perimeter here. Vercel documents All Deployments with Vercel Authentication at no additional cost on all plans. No protection has been enabled, disabled or bypassed by this task. [Protection scope documentation](https://vercel.com/docs/deployment-protection).

Vercel's authentication cookie is restricted to one URL, so completing provider authentication on a branch alias does not prove access to the unique deployment URL. Hobby permits only one external invited Vercel user per account. The owner-only demonstration may fit that restriction; arbitrary invited Forge viewers do not thereby gain Vercel access. Provider protection must be tested with both signed-out and explicitly authorized browser contexts on the exact issued URL, then retested after access revocation. Never put automation bypass credentials in links, browser cookies supplied by Forge, guest requests or public environment variables. [Vercel authentication documentation](https://vercel.com/docs/deployment-protection/methods-to-protect-deployments/vercel-authentication).

There is no verified authenticated network path from a Vercel-hosted gateway to the private canonical authority and Task 02's host-local Unix/vsock transport. It is not a directly deployable Vercel Function composition. Per-generation hostname issuance, retention, provider redirects during the ticket POST, exact protection settings/aliases, and account runtime/deployment quotas also remain untested. No new project, public proxy, tunnel, bypass token, subscription or domain was created to work around these gaps.

Thus default hostnames pass the **local browser site/cookie experiment**, but the full selected hosting arrangement remains unverified and disabled. There is no working private-preview URL to report.

## No-purchase alternative for review

Use the owner's existing machine as the HTTPS gateway, bound to loopback, and an authenticated SSH connection to an already owned hardened Task 02 runtime host. Give each preview a never-reused local hostname under a reserved `.test` name and locally trusted TLS material. The Forge website can remain on Vercel; configure its exact origin for the top-level launch POST. Do not publish the gateway listener or map it through a public tunnel. Local resolver/CA setup, the browser's public-to-local navigation restrictions, and authenticated runtime/control transport require a separate real-browser acceptance run before this option is enabled. This is an owner-device workflow, not a public link or a substitute for the missing isolated runtime. It purchases no domain or service, but still requires the existing host/access input.

## Lifecycle changes and limits

Tickets travel only in an exact-origin POST body. Native PostgreSQL atomically consumes the ticket and inserts a hashed session, bound to parent login, current membership, immutable hostname, tenant, project, environment, operation, generation and epoch. Consumption failures roll back. Sessions rotate on explicit same-origin renewal; neither renewal nor ordinary activity extends the two-hour absolute preview lifetime. A 200 launch page requires an explicit same-site link click so Strict cookies are reliably sent after the cross-site launch; the ticket never enters URL/history/referrer. Guest cookies are withheld; generated app authentication remains out of scope.

Every guest response is bounded, buffered and reauthorized before release. Expiry, revocation, stale environment/source/image/epoch, unhealthy runtime and timeout fail closed. Header allowlists withhold Forge/provider/deployment credentials. Requests use fixed private runtime RPC, never a user-selected URL. Redirects, WebSockets, service workers and streaming responses are unsupported in this first private gateway. Revocation fences routing and expires the environment for the canonical reconciler; actual destruction remains Task 02's responsibility. Route tombstones are retained permanently; no hostname reuse after destruction.
