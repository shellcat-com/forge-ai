# E0 contracts: review, progress and E1 handoff

Date: 2026-09-09. Status: **vendor-independent E0 implemented; D7 release-template finalization remains open**. This report is the progress checklist for [RFC 0001](../rfcs/0001-app-generation-vertical-slice.md). The required generated stack is Next.js App Router + strict TypeScript + PostgreSQL. No engine API, job worker, generated-code execution, infrastructure provisioning or service purchase is enabled by these changes.

| Blocker or contradiction | Resolution / decision |

| Three login methods, full onboarding and production deploy were mixed with private-alpha acceptance | Market goals remain later backlog. Alpha uses invite-only platform login, disposable test apps and private preview; no generated authentication or production data/deployment. |
| Global failure/expiry arrows could bypass CANCELLING cleanup | CANCELLING only exits CANCELLED after confirmed teardown/quarantine and access revocation. Reducer requires resource confirmation before terminal failure/expiry too; E1 must persist and fence pending cleanup without dispatching new work. |
| Approval identity lacked a persisted full review subject | Versioned plan/execution/promotion reviews bind tenant/job/base, policy/template, content and expiry; job stores the current versioned review object and digest. Approvals bind actor, exact digest and state version. Fresh locked context rejects stale revision/head, repaired source, revocation, cancellation and expiry. |

| Provider non-streaming completion had no payload; usage absence was ambiguous | Versioned completion carries either a structured product or terminates text deltas; reject both together, truncation, refusal, tools, missing completion and post-terminal output. One request produces one plan/batch. Usage remains optional and classified measured/estimated/uncertain. |
| “100 operations” could be interpreted per batch | Validate the assembled proposal, sequential indices, final marker, plan/base hashes, file ownership, expected prior hashes, protected paths, total operations and resulting source limits before any write. |
| Template, app DB and preview identities were underspecified | Fixed template ID and exact-release manifest format; no actual releases/images selected. Descriptor uses server UUID resources, fixed logical mounts, zero internet, app-local PostgreSQL and bounded limits. Preview generation is a unique UUID, distinct from integer fencing epoch. |
| Nullable/circular tenant FKs and job-specific candidate evidence were incomplete | Full initial control migration, delayed head/base/candidate FKs, composite workspace/project/job references, project identity on ticket/usage children, global identity references documented. No cross-project head even inside the same workspace. |
| Artifact/snapshot availability confused with execution authority | Available means readable validated artifact. Snapshot content is immutable and verified status requires an available verification artifact; project head requires verified source and revision increment. E1 still enforces approval/evidence/policy freshness in the promotion transaction. |
| Hash serialization and integer precision unspecified | Forge canonical JSON v1: sorted UTF-16 keys, JSON escaping, unchanged Unicode/arrays, safe integers, -0 → 0; rejects lossy/non-JSON inputs. SHA-256 over UTF-8; golden vectors. Database bigint values share safe-integer wire bounds; signed ledger adjustments are explicit. Never hash JSONB serialization. |
| E0 schema definition vs durable services/execution was unclear | Zod runtime schemas and TypeScript types are authoritative, including semantic refinements. Structural JSON Schema is exportable but cannot express all refinements. SQL enforces version/byte/relational constraints; E1 writers must also validate runtime schemas. No automatic grants, migration on startup, provider calls or executable adapter are added. |

## Exact E1 handoff

Implement `engine/control/` as a separately configured, initially disabled authenticated TypeScript service for RFC §5 `/api/v1/`. Reuse the v1 exports in [engine/contracts/index.ts](../../engine/contracts/index.ts) and migration 0001; append migrations rather than rewriting this one after acceptance. Do not expose or weaken `/api/provider` or `/api/generate`, and do not automatically apply migrations against an environment-provided database. Keep provider and runner integrations explicitly fake. No generated-code execution is authorized by E1.

1. Record D1/D4/D5 closure evidence before their external steps. Until then use a fixture identity adapter and ephemeral synthetic PostgreSQL. Resolve the separate cloud-auth prototype’s identity model/schema explicitly before integrating it; do not infer equivalence from shared dependency names.
2. Add environment validation with no secret defaults, fixed approved provider destinations, safe logging, default-off engine flags and operator kill switches. Define migration-owner, non-owner API, worker and maintenance role grants. Existing E0 migration grants no runtime role authority.
3. Implement OIDC authorization code + PKCE and opaque server sessions (12-hour absolute lifetime) behind an identity adapter; verify issuer/audience/signature/state/nonce, invite admission and revocation. Add CSRF, exact Origin, bootstrap-cookie login, one-use auth transactions and logout. Never infer identity from browser-local demo state.
4. Implement project/session/capability endpoints with current membership and role checks, tenant-safe 404/403 semantics, validated brief/stack/preset fields, optimistic revisions and explicit local brief import. Set/clear transaction-local workspace context only after authentication; add two-user/two-workspace and pooled-connection tests. Do not grant raw SQL or caller-selected GUC access.
5. Add atomic idempotent job admission: lock project/quota, verify base head/revision/template/policy, reserve bounded funds/concurrency and persist job, first queued step, event and idempotency response in one transaction. Deduplicate ledger entries; retain uncertain provider liabilities. Same key+body returns original outcome; different body conflicts.
6. Implement leased queue claim (`FOR UPDATE SKIP LOCKED`), 60-second monotonic epochs, 15-second heartbeat, worker state/version/epoch CAS and atomic sequenced event append. Persist stage input/output digests before dispatch, active-clock segments/deadlines, seven-day job age, queue/review expiry and cleanup state. A stale worker cannot commit an artifact, route, settlement or promotion. E0 reducer trusted inputs must come from these locked records and authenticated services, never HTTP/provider booleans.
7. Persist exact current review objects/digests and append-only approvals. Validate current membership, state version, base head/revision, expiry and policy revocation under locks. A repair always creates a new execution review. Promotion locks project/job, verifies current exact evidence, CAS-updates head/revision and appends success atomically; cancellation wins or returns already committed terminal status. Reject/revoke/expire must retain resource reservations until confirmed cleanup, with dispatch fenced.
8. Implement same-origin authenticated SSE with ordered replay, job-scoped cursor validation, deduplication, gaps/410 retention response, bounded slow-client buffering and periodic reauthorization. Closing the browser must not cancel the durable job. Add explicit cancellation and reconciler operations through narrowly scoped service functions.
9. Exit E1 only with native PostgreSQL two-tenant authorization/RLS, idempotency/reservation races, promotion/cancel serialization, lease fencing, duplicate completion, worker crash/restart, uncertain billing, timeout/cleanup and SSE reconnect/revocation tests against explicit fakes. Run `npm run verify`, `npm run test:db:control` and affected browser flows when UI integration exists. Report external-auth/hosting gates still blocked if owner inputs remain absent.

E2 then implements the real source adapter/context/artifact pipeline and immutable template/catalog checks; E3 implements broker authentication, signatures, microVM enforcement, app-local PostgreSQL/SQL policy, collector and cleanup. E4/E5 alone can close the real vertical-slice and release acceptance matrices.
