# Hosted generation request and free-call contracts

The engine's chat adapter has explicit dialects for the reviewed hosted catalog. Registry construction binds the provider, exact endpoint and allowlisted model before credentials can be read. Gemini uses its OpenAI compatibility endpoint with JSON output and thinking disabled for the reviewed 2.5 Flash candidate; Groq uses `max_completion_tokens` and `on_demand`, never OpenAI's invalid `default` tier. OpenRouter uses one exact `:free` model, no model list, fallback disabled, required-parameter enforcement and zero maximum prompt/completion/request/image prices. No tools or provider-selected endpoints are enabled.

A response must name the exact requested model. Unexpected Groq service tiers and any reported nonzero OpenRouter cost fail without adopting source. Quota, authentication, malformed JSON and model mismatch errors never initiate another call. Existing deadline, byte/token caps, schema validation, pinned DNS/TLS, secret-echo rejection and uncertain accounting remain in force. Injected HTTP responses retain fixture provenance. Missing cost telemetry is not proof of billing, and accepting a JSON request is not proof that a model reliably produces the source contract.

A zero-price policy must explicitly carry `freeOnly: true`, a digest of the reviewed entitlement evidence and a price validity window of at most 24 hours. Mixed zero/nonzero rates and implicit zero pricing are rejected. Registry installation only permits these policies for the supported hosted provider profiles. This data is trusted job configuration, never a price asserted by a browser. It does not discover an account's billing state or prevent a Gemini/Groq account owner changing that state; hosted dispatch still needs fresh authoritative entitlement/key/policy checks before enabling generation. No live free policy is installed by these changes.

Zero dollars does not mean unlimited calls: the same PostgreSQL reservation, unique request identity, job counter, lease gate and exactly-once dispatch CAS apply. Failed and uncertain calls keep their numbered attempt; settlement does not restore it. Native tests confirm twenty concurrent zero-price requests admit exactly twelve, then one dispatch winner per admitted request. A durable allowance across jobs and the actual hosted dispatch gate remain part of worker composition.

Verification uses explicit synthetic model responses and a disposable native PostgreSQL database. No live API key or model call is used. Before release, verify actual key entitlement and model/source behavior, preserve the exact evidence digest and expiry, connect the existing durable generation hooks to authorized job leases, and prove the full build/preview/publish flow. The generic E1 fixture worker remains disabled for hosted generation.
